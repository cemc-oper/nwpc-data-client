# 源文件检查与目标发布

`fetch` 不只复制路径：它先确认源文件就绪，再通过临时文件和无覆盖发布生成目标。
这些规则适用于普通本地文件、CMADAAS 挂载文件和 cmafs 下载文件。

## 源文件就绪检查

本地源文件必须：

1. 是普通文件且大小非零；
2. 在 `--stable-interval`（默认 `1s`）间隔的两次检查中，大小和修改时间不变；
3. copy 完成后仍保持相同大小和修改时间。

复制使用同一个已打开源文件描述符完成检查和读取，避免检查后被替换成另一个文件。
两次稳定观察只是就绪启发式，不进行 GRIB、NetCDF 等内容格式校验。

候选路径只在明确不存在时继续下一个；权限错误、目录、空文件或正在变化的文件都会
直接失败，不会改选其他数据源。`fetch` 不会持续等待产品生成；本地候选需要等待时可
使用 [`check local`](../check-local/index.md)，文件稳定后再执行后续任务。cmafs 不属于
`check local` 的轮询范围。

## 原子发布与并发

复制流程为：

```text
目标目录内唯一临时文件 → 复制与校验 → 无覆盖发布 → 删除临时名称
```

正式目标不会暴露仍在写入的半份文件。同一目标使用同目录锁文件进行跨进程互斥；
锁文件会保留，不能直接删除后假设没有其他等待者。进程异常退出可能留下唯一命名的
临时文件，清理由业务运行目录的维护策略负责。

收到 SIGHUP、SIGINT、SIGTERM 或 SIGQUIT 时，fetch 以退出码 3 返回，并清理本进程
临时文件。

## 重复执行与已有目标

已有目标按以下规则处理：

- copy 可复用大小非零且大小、mtime（Unix 秒）与源一致的普通文件；
- symlink 可复用指向完全相同源路径的符号链接；
- auto 可以复用合法普通文件；只有非 storage 的本地源可以复用同向 symlink，
  cmafs 不复用远端链接；
- 方法与目标类型不符、内容元数据不符、空文件或目录均报目标冲突；
- 任何情况下都不覆盖已有目标。

复用是操作幂等判断，不是密码学完整性校验。由于需要重新读取源元数据，源文件已经
删除时不能仅凭目标存在就判定为同一结果。

方法选择见 [fetch 基本指南](index.md)，目标冲突和临时文件的处理建议见
[脚本接入与故障排查](../troubleshooting.md)。
